# 雷霆裁决：Skill3 施法时序

2026-10-17：按用户要求，雷电释放时先播放小红帽 `Skill3`，抬手举起镰刀后才触发落雷。

## 行为

- 原有 1–3 秒随机计时改为提交施法请求；请求在当前攻击/技能完成后的动作间隙消费，不中途打断普通攻击或其他技能。
- Skill3 沿用正式角色骨架已有的 `OnHit` 事件（动画时间 2.08 秒）；实际 Unity 画面确认此时镰刀已举起。落雷特效、音效和伤害统一从该事件触发，随角色攻速同步，不使用独立固定秒数延迟。
- Skill3 完整结束后开始下一轮 1–3 秒计时。由于增加完整施法动作，雷电实际施放间隔包含动作等待及施法时长。
- 原有伤害倍率与“低于 50% 生命”条件保留。施法开始时记录目标，命中事件到达时重新检查存活、场景激活、入场状态与血量。不会将当前施法转移给新波次敌人。
- 同次动作只处理一次 OnHit；没有有效目标不空放。死亡、营地初始化、胜利和施法中切换到其他动作时清除待触发状态。
- 不改动 Skill3 骨架动画、正式雷电 Prefab 或缩放参数。雷电单独占用一次施法动作，不递增幽灵狼群的三次攻击计数。

## 实现与验证

运行逻辑：`Assets/Scripts/Combat/Player.cs`。验证工具：`Assets/Editor/Validation/LightningSkillValidation.cs`，通过显式本地请求运行，测试禁用存档写入，结束后恢复原场景。

实际 Unity 验证覆盖 720×1280、768×1024、720×1440，分别使用攻速 100、200、75：举镰刀阶段无落雷/伤害；2.08 动画秒事件后出现正式雷电并准确扣血；半血以上敌人不受击；重复事件不重复扣血；完整收招回到待机。另验证计时请求、死亡取消、回血目标复核与营地忽略过期事件。

截图与结果仅留在被忽略的 `output/lightning-skill/`：`validate-0/1/2-raised-before.png`、`validate-0/1/2-lightning.png` 与 `validate.txt`。测试抬高玩家和敌人生命以维持场景，未写入用户存档。未执行 APK 构建或真机性能验收。
