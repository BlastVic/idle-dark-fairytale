Artwork: ResultArtwork.png derives from battle-result-v1.png via built-in image_gen: remove all text and buttons while preserving panel contours, chest, lantern, wax seals and backdrop. ResultPanels.png further isolates the original paper silhouettes and interior illustrations onto transparency, keeping header and button regions blank. The background is a separate existing MoonlitCastleBattle image, covered uniformly across the supported screen region; UI art scales uniformly within the safe core. ResultButtons.png derives from the same reference: extract crimson and ivory button backgrounds without text, on transparency. Both are production derivatives, not a claim of pixel-identical extraction. Text, control labels, and currency costs are real Text components. Font, positions, button states, textures and action groups are editable on the prefabs.

Build is explicit only: Tools/Dark Fairytale/UI/Build Battle Results (Explicit). No rebuilding on scene load or asset import. Re-running this command replaces the two result prefabs and should only be used intentionally.

Victory and defeat use the existing Router transitions. Next-node action is shown only for the next visible battle node in the installed chapter map that satisfies prerequisites and has wave data. It is absent on defeat, locked progression, and the end of the currently exposed chapter. No unreleased chapter is entered.

Navigation locks until battle cleanup finishes and after the first click. Reward callbacks are idempotent per result session. Paid opening validates balance, charges once, and saves once. BattleResult ad callbacks bypass legacy automatic chest credit. Editor test emulates reward completion; live ad-provider playback is not verified because the project currently uses EditorAdMediationProxy, which reports ads unavailable.

The old victory/defeat roots remain inactive as LegacyVictoryBindings / LegacyDefeatBindings because legacy chest functions still hold references into them. They are no longer the displayed battle result screens. Removing those bindings requires the separate legacy chest-flow migration, not simply deleting the roots.

Validation evidence is local only under output/battle-result/. Runtime test progress/reward saving is disabled by MONSTER_QA_DISABLE_SAVE and restored on exiting play mode.

Final verification: Unity play-mode checks passed for 1080x1920 (9:16), 768x1024 (3:4), and 720x1440 (1:2), with actual rendered PNGs retained under ignored output/battle-result/. Checked next-node eligibility, hidden next action on defeat / final chapter node, UI raycasts, cleanup lock, duplicate navigation lock, once-only rewards, once-only currency debit, insufficient balance, simulated advertisement completion and repeated callback, real victory and defeat Router paths, replay and return to shelter. Result-home action directly starts GoToCampFromBattle instead of relying on the legacy menu's game-state switch. Forced-result QA stops combat scheduling before invoking outcome routes to prevent concurrent automatic combat during the test.

Visual comparison: paper borders and central illustrations derive from the selected result design. The backdrop uses the existing scene artwork so it fills wide screens without seams; the moon/background therefore differ from the concept. Button backgrounds are cleaned derivatives and real CJK type uses the project's installed font, with minor texture / glyph-weight differences. These differences remain visible; this delivery does not claim 100% pixel identity.
